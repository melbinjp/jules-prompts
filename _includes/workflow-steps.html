1. Set up the model and the person

    Turn one model into the agent that builds the project: it builds its own harness and tools if it has none, and proves them. Ask the person everything only they can answer, at the start, and set the standing limits. Then put the sandbox, the checkpoints and the gates in place, so development runs without waiting and nothing is called done until it passes.

    Done when the harness passes harness/conformance.py, the briefing is answered with its standing limits, and the sandbox, checkpoints and gates are in place.

    Calls on Keep a Project Confidential, Offline First, Choose Between Options with Evidence

  2. Start from the idea

    Work out what it takes to make the idea happen and how it is paid for. Make the few decisions that are costly to reverse with verified evidence. Make every stage of the pipeline a command a person or an agent can run, and build one thin slice end to end. The ledger it writes gives every later step its reasons. For a project that already exists, write the ledger from what is there.

    Done when the owner has agreed the path and its first step, the ledger passes the trace check, and the walking skeleton has run end to end and been rolled back once.

    Calls on Choose Between Options with Evidence, Design the Experience, with Evidence, Act on the Physical World, and Prove It Happened, Map the Architecture, Keep a Project Confidential, Offline First

  3. Make it run from cold

    Dependencies install, the tests run to completion, and nothing reports success while broken, so every later step starts from a baseline rather than an assumption.

    Done when a clean checkout installs and runs its tests with one command, and breaking a step makes that command fail.

    Calls on Isolate Tests from External Services

  4. Design what people and agents use

    Design every journey as a flow, with every state and every word, before breadth is built. Keep one system of look and behaviour in code, make every action operable by a person, an agent or automation with the same limits, and keep the design threaded to the architecture. Settle taste with the owner and everything else with evidence, and test each journey with people, or stand-ins labelled as such.

    Done when each journey that must never fail is a flow with every state and word designed, operable by a person and an agent with the same limits, threaded to the architecture with no empty cell, and tested with people or labelled stand-ins until its target holds.

    Calls on Choose Between Options with Evidence, Change a Project with a Reason, Act on the Physical World, and Prove It Happened

    repeat as needed

  5. Choose with evidence, whenever a choice matters

    Compare real options for each consequential choice, including building it and combining several. Use criteria from the goal, back the decision with at least two pieces of evidence (one verified), redo every number, and keep a way out.

    Done when the decision record passes the trace check, and the owner has approved it if it is costly to reverse.

    repeat as needed

  6. Build in changes that each have a reason

    Every milestone and every request, however vaguely worded, is translated into a measure, verified before and after, built through every layer it touches, and traced to the goal, with nothing left behind.

    Done when every claim in the request is accounted for, every commit has its Serves and Verified lines, the measure moved, and nothing is left detached.

    Calls on Scope a Vague Issue, Design the Experience, with Evidence, Fix a Bug, Failing Test First, Verify a Database Migration Before It Meets Real Data, Run the Error Paths, Act on the Physical World, and Prove It Happened

    repeat as needed

  7. Take it to production quality

    Write the bar, then close the gap in order of what it costs the people who use it: nothing lost, the core job on every platform, finished to use, nothing it does not need. Every item ends as holds, broken or skipped.

    Done when every row of the bar holds, or is broken or skipped with its reason and its next step in the plan.

    Calls on Design the Experience, with Evidence, Security Review of Agent-Written Code, Run the Error Paths, Prove the Documentation Against the Code, Map the Architecture, Act on the Physical World, and Prove It Happened, Release a Product to Its People, and Hear Back

    repeat as needed

  8. Review what the agent produced

    Check each pull request against the claims it makes about itself, and break the code under every new test to see it go red.

    Done when every claim the pull request makes is checked, and every new test has been seen to fail.

    Calls on QA the Tests an Agent Wrote, Prove the Fix by Making It Fail, Repair a Pipeline That Is Green Without Checking Anything

    repeat as needed

  9. Release it to its people, and hear back

    Walk every way in from a clean device as a stranger, make the listings, words, terms and privacy notice true to the product, stage the release so it pauses on its own and rolls back in one action, tell people where they already are in their words, and answer them. Measure each channel, and take the next route where one brought too few.

    Done when every way in works on every platform from a clean device, the listings and legal texts match the product, the rollout is staged with its pause threshold and a tried rollback, the help route is answered, and each channel's measure has been taken and its course change evaluated.

    Calls on Design the Experience, with Evidence, Choose Between Options with Evidence, Keep a Project Confidential, Offline First, Act on the Physical World, and Prove It Happened

    repeat as needed

  10. Keep it on course and improving, for good

    At every milestone and continuously after launch: take every measure again from its source, switch routes where a course change fired, remove what no longer serves the goal, run the pipeline both ways, and rank the next improvements. The project continues, adjusts, re-routes or grows; it is never left half-done.

    Done when every measure was taken from its source this run, the next improvements are ranked into the next milestone, and the ledger is committed. Then it starts again.

    Calls on Change a Project with a Reason, Choose Between Options with Evidence, Update Dependencies, Keep a Project Confidential, Offline First, Release a Product to Its People, and Hear Back, Handle an Incident, Restore First and Then Prevent It

    repeat as needed

  11. Restore it when it breaks, then prevent it

    Whenever a live product fails people: stop the harm to data, restore by the fastest action already tried, tell the people affected, and keep the evidence. Then find the cause with a failing test, fix it through the normal gates, put every person right, and close the class of failure in the system.

    Done when service is restored by a tried action, every person, record and device affected is put right and checked, the cause is proved by a test that fails without the fix, and each class of failure is closed by a test, an alert, a limit or a drilled procedure in the ledger.

    Calls on Change a Project with a Reason, Run the Error Paths, Act on the Physical World, and Prove It Happened

    repeat as needed

  12. Keep it current

    Update dependencies in small, verified steps, so staying current never becomes a rewrite.

    Done when each update is its own verified commit, and the suite passes on the new versions.
