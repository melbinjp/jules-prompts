The recommended sequence for a project in any state, software or physical: start it on written reasons, build it in traced changes, take it to production quality, and keep it on course after launch. Start at the first step for an idea, and at the second for a project that already exists.

  1. Start from the idea

    Decide whether it should exist, and write down what success is and when to stop. Make the few decisions that are costly to reverse with evidence. Make every stage of the pipeline a command a person or an agent can run, and build one thin slice end to end. The ledger it writes gives every later step its reasons. For a project that already exists, write the ledger from what is there.

  2. Make it run from cold

    Dependencies install, the tests run to completion, and nothing reports success while broken, so every later step starts from a baseline rather than an assumption.

  3. Choose with evidence, whenever a choice matters

    Compare real options for each consequential choice, including doing nothing, building it, and combining several. Use criteria from the goal and evidence in proportion to the stakes, redo every number, and keep a way out.

  4. Build in changes that each have a reason

    Every milestone and every request, including a vague one, is translated into a measure, measured before and after, built through every layer it touches, and traced to the goal, with nothing left behind.

    repeat as needed

  5. Take it to production quality

    Write the bar, then close the gap in order of what it costs the people who use it: nothing lost, the core job on every platform, finished to use, nothing it does not need. Every item ends as holds, broken or skipped.

    repeat as needed

  6. Review what the agent produced

    Check each pull request against the claims it makes about itself, and break the code under every new test to see it go red.

    repeat as needed

  7. Keep it on course, at every milestone and after launch

    Take every measure again from its source, reopen the decisions whose conditions fired, and remove what no longer serves the goal. Run the pipeline both ways, then decide with evidence to continue, adjust, pivot, pause or stop.

    repeat as needed

  8. Keep it current

    Update dependencies in small, verified steps, so staying current never becomes a rewrite.
